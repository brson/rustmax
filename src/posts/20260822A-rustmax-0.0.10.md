Rustmax 0.0.10 is released with 16 commits since 0.0.9.

This is an upgrade release.
Eleven of the re-exported crates moved to a new major version,
several with breaking changes you will see through `rmx`.

## Crate upgrades

- `base64` 0.22 → 0.23
- `comrak` 0.35 → 0.54
- `itertools` 0.14 → 0.15
- `num-bigint` 0.4 → 0.5
- `rand`, `rand_chacha`, `rand_pcg` 0.9 → 0.10
- `rustyline` 17 → 18
- `sha2` 0.10 → 0.11
- `syn` 2 → 3
- `tera` 1 → 2
- `toml` 0.9 → 1.1
- `zip` 7 → 8

Three of these will break code that uses them.

`rand` 0.10 renamed its core traits:
the old `RngCore` is now `Rng`, and the old `Rng` is now `RngExt`.
So the trait you import to call `random()`, `fill()` or `sample_iter()`
is now `RngExt`.
The rustmax prelude imports both, so prelude users see no change.
`SmallRng` is now unconditional, and the `small_rng` and `nightly` features are gone.

`sha2` 0.11 returns digests as `hybrid_array::Array`,
which does not implement `LowerHex`,
so `format!("{:x}", hasher.finalize())` no longer compiles.
Use `hex::encode` instead &mdash; `hex` is in rustmax too.

`tera` 2 is a rewrite.
`Tera::new` takes no arguments and no longer loads templates from a glob;
filters take `(Arg, Kwargs, &State)` instead of `(&Value, &HashMap<String, Value>)`;
and `Value` is an opaque struct built through `From` rather than an enum you match on.
Note that tera 2 puts glob loading behind its `glob_fs` feature,
which rustmax does not enable,
so `load_from_glob` is not available through `rmx::tera`.
Walk the directory yourself and use `add_template_file`.

## API rendering

The custom rustdoc renderer that produces the
[API documentation](/api/rustmax/index.html) got a pass for correctness and speed.

Its output is now checked against `cargo doc`'s own output
for a test crate exercising most Rust constructs.
Tuple struct fields were printing the numeric item id of each field
rather than its type, so `struct Tup(u32, String)` came out as `Tup(43, 44)`;
`self` receivers printed as `self: &Self`.
Signatures had been rendered twice, once as plain text and once as HTML,
and the two had drifted apart; they are now one renderer.

Rendering is also deterministic.
Two `HashMap`s were letting random iteration order into the output,
so two renders of the same input differed in 273 files.

Rendering the 352-crate documentation set took 52 seconds and two and a half
minutes of CPU; it now takes 11 seconds and 20 seconds of CPU.
Four repeated linear scans became lookups built once.

## Also

- `reqwest`'s `stream` feature is enabled in `rmx-feature-more`
  and `rmx-feature-more-portable`.
- The `libc` doc example is gated on `#[cfg(unix)]`,
  which fixes the Windows CI build.
- [`skim`](https://crates.io/crates/skim), a fuzzy finder, is on the tools radar.
- The [library](/library.html) books are rebuilt at their latest upstream commits.
